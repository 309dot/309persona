# 비공개 옵시디언 노트 연결

옵시디언 볼트의 `309-persona/` 폴더에 쓴 노트가 AI 답변의 근거가 되고, 방문자 화면의 "309의 기록 지도"에 점으로 나타난다.

- 노트 원문은 **비공개 GitHub 저장소**에만 있다. 서버가 읽기 전용 토큰으로 받아 오고, 이 공개 레포에는 들어오지 않는다.
- 기록 지도에는 노트 제목과 연결만 나가고 본문은 나가지 않는다. 다만 AI는 본문으로 답하므로 방문자가 물으면 내용을 말할 수 있다. **말해도 되는 것만** 넣는다.

```
옵시디언 볼트/309-persona ──(동기화 스크립트, 내 컴퓨터)──▶ 비공개 저장소
        ──(서버 시작 때, 또는 대시보드 "다시 불러오기")──▶ 답변의 근거 + 기록 지도
```

## 처음 한 번 설정

1. **비공개 저장소**: GitHub에서 Private 저장소(예: `309persona-notes`)를 만들고 내 컴퓨터에 clone한다.
2. **읽기 전용 토큰**: GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token
   - Repository access: Only select repositories → 노트 저장소 하나만
   - Repository permissions → Contents: **Read-only** (다른 권한은 주지 않는다)
   - 만료일을 정해 두고, 만료되면 새로 발급해 바꾼다(대시보드에 401/403 오류로 보인다).
3. **Render 환경 변수**
   ```
   NOTES_GITHUB_REPO=309dot/309persona-notes
   NOTES_GITHUB_TOKEN=<위에서 만든 토큰>
   NOTES_GITHUB_REF=main
   NOTES_SUBDIR=309-persona
   ```
4. 볼트에 `309-persona/` 폴더를 만든다.

## 노트 쓰는 법

한 노트에 한 주제(프로젝트 하나, 사례 하나, 생각 하나)를 쓴다. 맨 위 속성(Properties)은 모두 선택이다.

| 속성 | 예 | 쓰임 |
|---|---|---|
| `type` | `프로젝트`, `사례`, `경력`, `생각`, `역량` (또는 project, story, career, value, skill) | 지도 분류. 분량을 넘으면 프로젝트 → 경력 → 사례 → 생각 → 역량 순으로 넣는다 |
| `title` | 페이히어 디자인 시스템 회고 | 근거 칩과 지도에 보이는 이름. 없으면 파일 이름 |
| `period`, `company`, `role` | 2022.11–2023.12 / 페이히어 / Senior Product Designer | 본문 앞에 붙어 AI가 사실로 쓴다 |
| `project` | `P2` 또는 프로젝트 제목 | 지도에서 지식팩의 프로젝트와 이어진다 |
| `portfolio_pages` | `6-11` | 포트폴리오 PDF 쪽. 본문 앞에 붙고, 이 노트가 답변 근거가 되면 답변 아래 카드·근거 칩·지도에서 포트폴리오 뷰어가 그 쪽으로 열린다 |
| `tags` | `[디자인 시스템, 협업]` | 지도의 주제 점. 본문의 `#태그`도 같다 |
| `aliases` | `[디자인 시스템 회고]` | 다른 노트의 `[[링크]]`와 질문 단어를 맞출 때 쓴다 |
| `question` | 디자인 시스템을 팀에 정착시킨 방법은? | 지도에서 이 노트를 누르면 묻는 질문 |
| `draft: true` | | 이 노트는 읽지 않는다 |

한국어 속성 이름(유형, 제목, 기간, 회사, 역할, 프로젝트, 포트폴리오, 태그, 별칭, 질문, 초안)도 받는다.

**서버가 알아서 정리하는 것**: `[[링크]]`는 글자로 바꾸고 연결은 지도에 반영, `![[임베드]]`·이미지·`%%주석%%`·HTML 주석·Dataview 같은 쿼리 블록은 뺌, 콜아웃은 표시만 지우고 글은 남김, `==강조==`는 글자만, 블록 id 삭제, 전화번호가 있는 줄 삭제, `309designlab.com`이 아닌 이메일은 가림.

**읽지 않는 것**: `_`나 `.`으로 시작하는 파일·폴더(템플릿, `.obsidian`), `draft: true`나 `persona: false`인 노트, 200KB가 넘는 파일, 저장소 안에서 `NOTES_SUBDIR` 밖에 있는 파일.

**쓰지 말 것**: "이렇게 답해줘" 같은 지시문(사실처럼 답변에 새어 나온다), 공개하면 안 되는 수치·실명·내부 정보, 출처를 댈 수 없는 숫자.

### 프로젝트 노트 템플릿

볼트의 `309-persona/_템플릿/프로젝트.md`로 두면(`_`로 시작해서 서버가 읽지 않는다) 옵시디언 템플릿 기능으로 쓸 수 있다.

```markdown
---
type: 프로젝트
title:
period:
company:
role:
project:
portfolio_pages:
tags: []
question:
---
## 배경과 문제

## 내 역할

## 결정과 버린 대안

## 결과 (수치는 출처와 함께)

## 실패와 배운 점
```

답변의 깊이는 "결정과 버린 대안", "실패와 배운 점" 같은 칸에서 나온다. 지금 공개 자료의 프로젝트는 제목과 성과 한 줄뿐이라 이 칸을 채울수록 "그때 왜 그렇게 했어요?"에 답할 수 있다.

## 동기화

볼트가 있는 컴퓨터에서 실행한다(파이썬 3만 있으면 된다).

```bash
python3 backend/scripts/sync_obsidian_notes.py \
  --vault ~/Obsidian/내볼트 --notes-repo ~/code/309persona-notes --push
```

- 볼트의 `309-persona/` 아래 마크다운만 복사하고, 볼트에서 지운 노트는 저장소에서도 지운다.
- 전화번호·이메일·"대외비/비공개/NDA/연봉" 같은 단어가 있는 줄을 알려 준다(막지는 않는다).
- `--dry-run`으로 바뀔 내용만 먼저 볼 수 있다. `--push` 없이 실행하면 커밋은 직접 한다.
- 그다음 관리자 대시보드 → "지식베이스 · 비공개 노트" → **다시 불러오기**. 재배포 없이 반영되고, 사용 중인 노트·분량·오류가 보인다.

## 분량과 비용

- direct 파이프라인은 노트를 프롬프트에 전부 넣는다. 검색으로 고르지 않으니 빠뜨리는 노트가 없다.
- `NOTES_MAX_CHARS`(기본 6만 자)를 넘으면 우선순위가 낮은 노트부터 빠진다. 대시보드에 "제외"로 보인다.
- 노트가 늘면 질문마다 보내는 입력이 커져 비용과 첫 글자 시간이 늘어난다. 지금 공개 자료가 약 9천 자이니, 노트는 몇만 자 안쪽이 적당하다. 그보다 커지면 노트 단위 검색으로 바꾼다.
- legacy 파이프라인은 노트도 빈 줄 단위로 쪼개 검색한다(출처 `note:슬러그#번호`).

## 로컬 개발

`backend/.env.local`에 볼트 경로를 넣으면 저장소 없이 바로 읽는다.

```
NOTES_DIR=/Users/me/Obsidian/내볼트
NOTES_SUBDIR=309-persona
```

브라우저 QA는 가짜 노트(`qa/e2e/notes/`)로 돈다(`QA_NOTES=1`, `qa/e2e/README.md`).

## 문제 해결

- "NOTES_GITHUB_TOKEN이 비어 있어요", "GitHub가 404로 응답했어요": 저장소 이름·브랜치와 토큰 권한을 확인한다. 토큰이 그 저장소를 허용하지 않아도 404가 난다.
- 노트가 0개: `NOTES_SUBDIR`가 저장소 안 폴더 이름과 같은지 확인한다.
- 불러오기에 실패하면 5분 뒤 다음 요청 때 다시 시도한다. 그동안에도 공개 자료로는 답한다.

## 개인정보

노트는 질문과 함께 AI 모델 제공사로 전송된다. 무료 등급 모델은 제공사가 입력을 서비스 개선에 쓸 수 있으니, 그래도 괜찮은 내용만 넣는다.
